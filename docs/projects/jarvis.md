# J.A.R.V.I.S. — 개발 기록

> Python과 로컬 AI를 이용해 직접 만들고 있는 개인용 음성 비서 프로젝트  
> 이 문서는 프로젝트를 개발하면서 시도한 것, 발생한 오류, 해결 과정과 현재 상태를 기록한다.

## 프로젝트 소개

J.A.R.V.I.S.는 음성 명령을 인식하고, 로컬 AI 모델을 통해 응답하며, 음성으로 답하는 개인용 AI 비서를 목표로 한다.  
처음에는 간단한 Python 기반 대화 프로그램으로 시작했고, 이후 호출어 감지, 음성 입출력, GUI와 프로그램 실행 기능을 단계적으로 추가했다.

## 개발 환경

- 운영체제: Windows
- 언어: Python
- 로컬 AI: Ollama + `qwen2.5:3b`
- 음성 인식: Faster-Whisper
- 음성 입력: `sounddevice`, `numpy`
- 음성 출력: Coqui TTS / `pyttsx3` 실험
- GUI: CustomTkinter
- 기타: `requests`, `webbrowser`, `subprocess`

> 개발 중 환경과 라이브러리는 여러 차례 변경되었다. 아래 내용은 현재까지 대화에서 확인된 개발 과정이며, 일부 세부 설정은 실제 프로젝트 파일과 대조해 보완할 수 있다.

## 개발 과정과 시행착오

### 1. OpenAI API 기반 시도에서 로컬 AI로 전환

처음에는 OpenAI API를 사용해 JARVIS의 대화 기능을 만들려고 했다.

**문제**
- Python에서 필요한 모듈을 설치해야 했다.
- API 키 설정 문제가 발생했다.
- API 사용 중 `429` 오류와 크레딧 문제가 발생했다.

**방향 전환**
- 외부 API 사용에 의존하지 않는 무료·로컬 실행 방식을 목표로 바꿨다.
- Ollama를 설치하고 `qwen2.5:3b` 모델을 사용했다.
- Python에서 Ollama의 로컬 API인 `http://localhost:11434/api/chat`에 요청하도록 구성했다.

### 2. Ollama 실행 문제

로컬 모델을 실행하는 과정에서 CUDA/PTX 관련 오류가 발생했다.

**시도한 해결**
- Ollama 실행 로그와 모델 실행 상태를 확인했다.
- GPU 실행 문제를 우회하기 위해 CPU 실행 환경 변수인 `OLLAMA_LLM_LIBRARY=cpu`를 사용했다.
- 이후 모델이 응답하는 것을 확인했다.

### 3. 음성 입력과 호출어 감지

키보드 입력뿐 아니라 음성으로 JARVIS를 호출하고 명령을 전달하는 기능을 개발했다.

**사용한 구성**
- `sounddevice`로 마이크 음성을 입력받았다.
- `numpy`로 오디오 데이터를 처리했다.
- Faster-Whisper로 음성을 텍스트로 변환했다.
- `Hey Jarvis` 호출어를 감지한 뒤 명령을 받는 흐름을 만들었다.

**문제와 디버깅**
- 처음에는 마이크 입력 음량이 0으로 표시되는 문제가 있었다.
- 입력 장치를 확인하고 헤드셋 마이크를 선택하는 과정을 거쳤다.
- 장치 목록에서 `마이크(WG1)`를 확인했으며, 입력 레벨을 테스트했다.
- 한국어 음성 인식 결과가 실제 발화와 다르게 나오는 경우가 있었다. 예를 들어 메모장 명령이 다른 단어로 인식되었다.
- 인식 결과를 보정하는 단어 매핑을 추가하는 방향을 시도했다.

### 4. 음성 출력(TTS) 추가

JARVIS가 텍스트로만 답하지 않고 음성으로 말하도록 TTS 기능을 개발했다.

**시도한 기술**
- `pyttsx3`
- Coqui TTS
- XTTS v2 모델
- FFmpeg

**문제와 해결 과정**
- TTS 라이브러리 설치 및 import 문제를 해결했다.
- FFmpeg가 설치되어 있어도 PATH에 등록되지 않아 명령을 인식하지 못하는 문제가 있었다.
- FFmpeg의 `bin` 경로를 PATH에 추가해 실행을 확인했다.
- 음성 생성과 재생이 동작하는 것을 확인했다.
- 음성 생성에 수십 초 이상 걸리는 경우가 있어 속도 개선이 다음 과제로 남았다.
- 한국어 음성 품질과 영어 음성 출력도 함께 실험했다.

### 5. GUI 개발

터미널에서 실행하던 JARVIS를 GUI로 조작할 수 있도록 CustomTkinter 기반 화면을 만들었다.

**진행 내용**
- JARVIS 이미지와 UI 요소를 배치했다.
- UI가 동작하도록 버튼과 실행 흐름을 연결했다.
- 영어 음성과 한국어 번역을 함께 표시하는 방향도 시도했다.

**문제**
- UI 초기화 과정에서 오류가 발생했다.
- `ui.py`에서 JARVIS 모듈을 import할 때 패키지 경로 오류가 발생했다.
- `JARVIS` 폴더와 `JARVIS.py` 파일의 이름이 겹치면서 Python이 패키지를 올바르게 찾지 못하는 문제가 있었다.
- `voice_engine` 모듈을 찾지 못하는 오류도 발생했다.

이 과정에서 파일을 분리한 프로젝트의 폴더 구조와 실행 위치, import 경로를 정확히 맞추는 것이 중요하다는 점을 확인했다.

### 6. 프로그램 실행 명령

음성 명령으로 Windows 프로그램을 실행하는 기능도 추가했다.

- 메모장 실행
- 계산기 실행

음성으로 “메모장이랑 계산기 켜줘”라고 요청했을 때 메모장만 실행되는 등, 한 문장에 포함된 복수 명령을 모두 처리하는 부분은 추가 개선이 필요했다.

### 7. 프로젝트 구조 정리

기능이 늘어나면서 코드 한 파일에 모든 기능을 넣는 대신, UI와 음성 엔진 등 역할별로 파일을 분리하는 방향으로 개발했다.

이 과정에서 확인한 점:

- Python 파일명과 폴더명이 충돌하지 않도록 해야 한다.
- 패키지로 import할 때 실행 위치와 경로가 중요하다.
- UI와 음성 처리처럼 오래 걸리는 작업은 별도 스레드 등을 고려해야 한다.
- 로컬 AI를 사용해도 모델 추론과 음성 생성 속도는 하드웨어 영향을 받는다.
